
# 🚀 AWS EC2 (Elastic Compute Cloud) – Complete Guide
## 🖥️ What is Amazon EC2?
 * Amazon EC2 (`Elastic Compute Cloud`) is a web service that provides **resizable compute capacity in the cloud**.
 * 👉 It allows you to run virtual servers (`instances`) without managing physical hardware.

## ✨ Key Features of EC2
 * 🔄 Easily scale instances up or down
 * 💰 Pay-as-you-go pricing model
 * 🧩 Multiple instance types for different workloads

---

## 🧠 EC2 Instance Types (Use Cases)
| 🎯 **Use Case**              | 🖥️ **Instance Type** | 🧠 **Optimized For**             | 💡 **Examples**          | 🚀 **Common Workloads**              |
| ---------------------------- | --------------------- | -------------------------------- | ------------------------ | ------------------------------------ |
| 🌐 **Websites & Small Apps** | ⚖️ General Purpose    | Balanced CPU, memory, networking | `t3`, `t4g`, `m5`, `m6i` | Web apps, APIs, dev/test             |
| ⚡ **High CPU Workloads**     | 🧮 Compute Optimized  | High-performance processors      | `c5`, `c6i`, `c7g`       | CI/CD, batch jobs, gaming servers    |
| 🗄️ **Databases & Caching**  | 🧠 Memory Optimized   | Large RAM capacity               | `r5`, `r6g`, `x2idn`     | Redis, SAP HANA, analytics           |
| 📊 **Big Data & Storage**    | 💾 Storage Optimized  | High disk throughput & IOPS      | `i3`, `i4i`, `d3`        | Elasticsearch, Kafka                 |
| 🤖 **AI/ML & Graphics**      | 🎮 GPU Instances      | GPU acceleration                 | `p4`, `g5`, `inf2`       | AI training, ML inference, rendering |

## 💰 EC2 Pricing Models
| 💳 **Pricing Model**           | 📖 **Meaning**                       | 🧠 **How It Works**             | 💡 **Best Use Case**           | ⚠️ **Important Note**    |
| ------------------------------ | ------------------------------------ | ------------------------------- | ------------------------------ | ------------------------ |
| 🟢 **On-Demand**               | Pay per usage                        | No long-term commitment         | Dev/Test, short workloads      | 💸 Most expensive        |
| 🔵 **Reserved Instances (RI)** | Long-term discounted pricing         | Commit for 1 or 3 years         | Stable production workloads    | 💰 Large cost savings    |
| 🟡 **Spot Instances**          | Unused AWS capacity at very low cost | AWS can terminate anytime       | Batch jobs, CI/CD, AI training | ⚠️ Interruptible         |
| 🟣 **Savings Plans**           | Flexible discounted pricing          | Commit to usage amount ($/hour) | Modern cloud workloads         | 🔄 More flexible than RI |


## 🛑 Stop vs Terminate
| Action | Result |
|-------|--------|
| Stop | Instance shuts down (data safe) |
| Terminate | Instance deleted (data lost) |

## 💾 Storage (EBS vs Instance Store)
| 🧩 **Feature**         | 💽 **EBS (Elastic Block Store)** | ⚡ **Instance Store**      | 🧠 **Explanation**                               | 🎯 **Best Use Case**           |
| ---------------------- | -------------------------------- | ------------------------- | ------------------------------------------------ | ------------------------------ |
| 🔒 **Persistence**     | ✅ Persistent                     | ❌ Ephemeral               | EBS survives stop/start; Instance Store does not | Durable vs temporary storage   |
| 🛡️ **Data Safety**    | ✅ Retained                       | ❌ Lost on stop/terminate  | Instance Store data disappears if instance stops | Critical vs temporary data     |
| ⚡ **Performance**      | High                             | 🚀 Very high (local disk) | Instance Store is physically attached to host    | High-speed temporary workloads |
| 🔄 **Detach / Attach** | ✅ Yes                            | ❌ No                      | EBS can move between instances                   | Flexible storage               |
| 📸 **Snapshots**       | ✅ Supported                      | ❌ Not supported           | EBS integrates with snapshots/backups            | Disaster recovery              |
| 💰 **Cost**            | Separate billing                 | Included with instance    | EBS charged separately                           | Pricing difference             |

## 🔐 Networking & Security
| 🧩 **Concept**              | 📖 **Meaning**           | 🧠 **Detailed Explanation**                                                   | 💡 **Example Use Case**                |
| --------------------------- | ------------------------ | ----------------------------------------------------------------------------- | -------------------------------------- |
| 🌐 **Elastic IP (EIP)**     | Static public IP address | Persistent public IPv4 address that can be attached/remapped to EC2 instances | Stable public endpoint for web servers |
| 🛡️ **Security Group (SG)** | Instance-level firewall  | Controls inbound/outbound traffic for EC2 instances                           | Allow HTTP (80) & SSH (22)             |
| 🚧 **NACL (Network ACL)**   | Subnet-level firewall    | Stateless security layer controlling subnet traffic                           | Block suspicious IP ranges             |
| 📸 **Snapshot**             | EBS backup               | Point-in-time backup of EBS volume stored in S3                               | Disaster recovery & backups            |

## 🌍 Public vs Private IP
| 🧩 **IP Type**    | 📖 **Purpose**             | 🧠 **Detailed Explanation**           | 💡 **Example**                  | 🎯 **Common Use Case**            |
| ----------------- | -------------------------- | ------------------------------------- | ------------------------------- | --------------------------------- |
| 🌍 **Public IP**  | Internet communication     | Reachable over the internet           | Web server public access        | Websites, APIs, SSH from internet |
| 🔒 **Private IP** | Internal VPC communication | Used only inside private networks/VPC | Database internal communication | App ↔ DB communication            |

 * Deploy across multiple AZs
 * Use Load Balancer

 * Instance terminated → Restore using `AMI/Snapshot`
 * Slow instance → Check `CPU/Memory`, `upgrade type`

## 🔗 EC2 to RDS Secure Connection
| 🔢 **Step** | 🧩 **Component**         | 🧠 **What It Does**              | 💡 **Why It Matters**                     |
| ----------- | ------------------------ | -------------------------------- | ----------------------------------------- |
| 1️⃣         | 🌐 Same VPC              | Keep EC2 and RDS inside same VPC | Enables secure private communication      |
| 2️⃣         | 🔒 RDS in Private Subnet | Database not exposed to internet | Prevents direct external access           |
| 3️⃣         | 🛡️ Security Group Rules | Allow DB port only from EC2 SG (3306 / 5432) | Restricts database access securely  |
| 4️⃣         | 🔑 IAM Roles / IAM Auth  | Avoid hardcoded DB credentials   | Improves security & credential management |

## 🚀 Steps to Launch EC2
| 🔢 Step | 🛠️ Action                   | 📘 Description                                    |
| ------- | ---------------------------- | ------------------------------------------------- |
| 🔐 1️⃣  | ☁️ **Login to AWS Console**  | Sign in to your AWS account securely              |
| 🖥️ 2️⃣ | 📂 **Open EC2 Service**      | Navigate to the EC2 Dashboard from AWS Services   |
| 🚀 3️⃣  | 🆕 **Click Launch Instance** | Start creating a new EC2 virtual machine          |
| 🐧 4️⃣  | 📀 **Choose AMI**            | Select OS image like `Amazon Linux` 🟡 or `Ubuntu `🟠 |
| ⚙️ 5️⃣  | 💻 **Select Instance Type**  | Choose compute type such as `t2.micro`            |
| 🔑 6️⃣  | 🛡️ **Create Key Pair**      | Generate `SSH key pair for secure access `          |
| 🌐 7️⃣  | 🔒 **Configure Network**     | Set `VPC`, `subnet`, `firewall` (Security Groups)   |
| 💾 8️⃣  | 📦 **Add Storage**           | Attach and configure EBS storage                  |
| ✅ 9️⃣   | 🎯 **Review & Launch**       | Verify settings and launch EC2 instance 🚀        |
