## 🔗 VPC Peering
 * VPC Peering connects `two VPCs` privately for secure communication. using `private IP` addresses without using the `internet`.

### 🔗 Steps to Create VPC Peering in AWS
| 🔢 Step     | 🛠️ Action                       | 📘 Details                                               |
| ----------- | -------------------------------- | -------------------------------------------------------- |
| 🌐 **1️⃣**  | 📂 **Open VPC Dashboard**        | Login to AWS Console and open the VPC Dashboard          |
| 🔗 **2️⃣**  | 📡 **Go to Peering Connections** | Click **Peering Connections** from the left-side menu    |
|             | ➕                                | Click **Create peering connection**                      |
| ⚙️ **3️⃣**  | 📝 **Provide Peering Details**   | Configure VPC peering settings                           |
|             | 🏷️                              | **Name:** `My-Peering`                                   |
|             | 🌍                               | **Requester VPC:** `VPC-A`                               |
|             | 🌎                               | **Accepter VPC:** `VPC-B`                                |
| ✅ **4️⃣**   | 🚀 **Create Peering Connection** | Click **Create**                                         |
| 🤝 **5️⃣**  | ✔️ **Accept Peering Request**    | If same AWS account → Accept directly                    |
|             | 🔐                               | If different AWS account → Accepter account must approve |
| 🛣️ **6️⃣** | 📡 **Update Route Tables**       | Add routes in both VPC route tables                      |
| 🔒 **7️⃣**  | 🛡️ **Update Security Groups**   | Allow traffic between VPC CIDR blocks                    |

# 🌉 Transit Gateway
 * Transit Gateway acts like a central router connecting multiple VPCs and and on-premises networks together.
 * It simplifies network management in large AWS environments.

### 🔥 Key Features of Transit Gateway
| 🧩 **Feature**              | 📖 **Description**                | 🧠 **Detailed Explanation**                   | 
| --------------------------- | --------------------------------- | --------------------------------------------- | 
| 🎯 **Central Hub**          | Connects multiple VPCs            | Acts as a hub for VPC and VPN connectivity    |
| 📈 **Scalable**             | Supports thousands of connections | Designed for large enterprise environments    |
| 🔄 **Transitive Routing**   | Supported                         | VPCs can communicate through Transit Gateway  | 
| 🌉 **Hybrid Connectivity**  | Connects on-premises networks     | Integrates VPN and Direct Connect             |
| 🌍 **Cross-Region Support** | Works across AWS regions          | Connect Transit Gateways in different regions |

# 🚪 VPC Endpoints
 * `VPC Endpoint` in AWS enables `private connectivity` between a `VPC and AWS services` without using the internet, Internet Gateway, or NAT Gateway. (S3, DynamoDB)

### 🔗 Steps to Create a VPC Endpoint in AWS
| 🔢 Step        | 🛠️ Action                                     | 📘 Details                                                                            |
| -------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------- |
| 🔐 **1️⃣**     | ☁️ **Login to AWS Console**                    | Open [AWS Management Console]                                                        |
| 🌐 **2️⃣**     | 📂 **Open VPC Dashboard**                      | Search for **VPC** and open the VPC Dashboard                                         |
| 🔗 **3️⃣**     | 📡 **Go to Endpoints**                         | From the left-side menu click **Endpoints**                                           |
| ➕ **4️⃣**      | 🚀 **Create Endpoint**                         | Click **Create endpoint**                                                             |
| ⚙️ **5️⃣**     | 📝 **Configure Endpoint**                      | Enter **Name tag:** `My-VPC-Endpoint`                                                 |
| 🏷️ **6️⃣**    | 🌍 **Select Service Category**                 | Choose **Gateway** or **Interface**                                                   |
| ☁️ **7️⃣**     | 🔍 **Select AWS Service**                      | Example: `com.amazonaws.region.s3`                                                    |
| 🌐 **8️⃣**     | 📂 **Select VPC**                              | Choose your VPC                                                                       |
| 🏢 **9️⃣**     | 🔒 **Configure Subnets** *(Interface only)*    | Select private subnets                                                                |

| ✅ **1️⃣2️⃣**   | 🎯 **Create Endpoint**                         | Click **Create endpoint**                                                             |

# 🌐 IP Support
 * AWS VPC supports `private IPs`, `public IPs`, `Elastic IPs`, `IPv4`, and `IPv6 addressing`.
 * Private IPs are used for `internal communication`, while `public` and `Elastic IPs` provide `internet connectivity`.

---

# 📏 CIDR Block

- 🌟 CIDR (Classless Inter-Domain Routing) is a method used to define the range of IP addresses in a VPC and subnets.
- 🔥 Example: `10.0.0.0/16` → 65,536 IPs
- 🌍 CIDR is important because it determines the `network size`, `subnet structure`, available `IP addresses`, and routing design in AWS VPC..
